# tricks-v1: задачи с подвохами

28 задач, по 7 каждого типа. Каждая задача содержит ловушку для агента или для короткого пути без LLM: регулярных выражений, проверок «есть ли файл или человек», разбора хвоста условия. Набор диагностический: по нему видно, на каком подвохе агент ломается.

Формат как у организаторов (`workspace/`, `mylib.py`, `test_mylib.py`, награды 1–5, поле `check`), но формулировки намеренно отклоняются от образца там, где в этом и состоит подвох.

Во всех задачах объёмные комментарии на русском, описание поведения только в комментариях, а имена функций и классов вводят в заблуждение. У всех есть скрытые тесты.

У четырёх задач кода есть «узкое» исправление, которое проходит видимые тесты и проваливает скрытые.

## Как запустить

Из корня репозитория. Тесты кода импортируют `numpy`, `pandas` и `python-dateutil`, поэтому проверка идёт в образе агента.

```bash
python benchmarks/tricks-v1/build.py
python benchmarks/tricks-v1/validate.py --image hack:latest
```

`validate.py` не вызывает модели и проверяет:
- быстрые алгоритмы математики сверены с перебором на малых числах;
- во входах только официальные поля и нет слова IMPOSSIBLE;
- исходный код падает, эталон проходит видимые и скрытые тесты, узкие исправления проходят только видимые;
- `evaluation/grade` даёт идеальным ответам максимум, а ответы на невыполнимые задачи отмечает как ложные.

Прогон агента: в контейнер монтируется **только копия `input/`**.

```bash
cp -r benchmarks/tricks-v1/input benchmark-runs/tricks-01
# запустить агента на benchmark-runs/tricks-01
python -m evaluation.grade --references benchmarks/tricks-v1 --run benchmark-runs/tricks-01 --docker hack:latest
```

## Ограничения

- **Какие библиотеки есть в среде проверки организаторов, неизвестно.** Задачи с `numpy`, `pandas` и `dateutil` проверяют работу агента в нашем образе.
- Оценщик для кода требует `DONE` в `answer.txt`, в том числе в задаче без инструкции про DONE: организаторы просили создавать `answer.txt` всегда.
- Ответ в `search_0002` с опечаткой в имени и решаемость задач с опечатками — наше допущение: в финале такие задачи могут считаться невыполнимыми.
- Модели на этом наборе ещё не запускались.
