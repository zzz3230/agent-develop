# Качественные примеры для MiniLM

Исходники — diverse-v1 (64 задачи), gaps-v1 (40) и tricks-v1 (28).
Старый benchmark100 не используется. Все 132 исходные задачи перечислены
в manifest.json с хешами входов, группой алгоритма и назначением части.

Обучение: **88 задач** — 39 diverse, 31 gaps, 18 tricks. Отложенная часть:
**44 задачи**. Все исходные holdout diverse сохранены; один dev перенесён
в проверку из-за повтора алгоритма. В gaps/tricks часть
выбрана с фиксированным seed 20261114. Очевидные пересечения — стабильная
дедупликация, рабочие дни, округление и сравнение версий — объединены в группы.
Если участник группы попал в проверку, вся группа исключена из обучения.
Это устраняет известные дубли, но не доказывает полной семантической независимости.

Разметка — фактическая правильность после проверки и полный расход попытки,
а не только признак выполнимости. 108 совместимых измерений взяты из готовых
прогонов агента: diverse dev и опубликованные gaps/tricks. Их код решателя
соответствует 945ecb7; между ним и используемым f8e23ac менялись только
планирование и предикторы, а не выполнение отдельной попытки. Полные хеши
образов для опубликованных gaps/tricks не сохранены, поэтому это исторические
замеры с известной версией кода, а не доказательство идентичности окружения.
Старый полный прогон diverse на fbb2b3 не использован: решатель после него менялся.
Недостающие 24 diverse holdout измерены заново на f8e23ac после фиксации моделей.

Обе новые модели учатся с нуля на одинаковых 88 строках, из которых 74 успешны.
Используются замороженный MiniLM INT8, логистическая регрессия и Ridge-регрессия.
Разница вариантов — 45 обычных признаков с ключевыми словами либо 18 без них;
к каждому в обоих случаях добавляются 384 числа эмбеддинга. Нормализация
и подбор регуляризации выполняются только на обучающей части, по пяти группам.
Ни reward, ни ID, ни ответы, ни скрытые тесты не входят в признаки.

Компактные измерения и обучение: `docs/results/quality-minilm-v1/`.
Оценочные 200 экземпляров из отложенных групп: `benchmarks/quality-holdout-200/`.
Они отличаются от прежних 200, на которых выбирался лучший старый предиктор.
Прямое сравнение баллов этих разных наборов некорректно.

Подготовка и обучение из корня репозитория:

```powershell
python -m evaluation.quality_dataset
python -m evaluation.download_encoder
python -m evaluation.train_quality_minilm
python -m evaluation.quality_experiment collect
python -m evaluation.quality_experiment validate
```

Обучение и validate требуют окружения из
`evaluation/predictor-training-requirements.txt`. collect повторно использует
опубликованные 24 замера при отсутствии локального прогона. Для нового
независимого измерения удалять опубликованные данные не нужно — создайте
отдельный запуск через evaluation.run_image.

Сборка поверх образа agent-develop:predictor-policies:

```powershell
docker build -f evaluation/Dockerfile.quality-minilm -t agent-develop:quality-minilm .
python -m evaluation.quality_experiment compare
```

Основа и энкодер описаны в docs/offline-predictors.md. Для compare нужны
LLM_API_KEY и LLM_BASE_URL в окружении. Два варианта проходят по одному разу,
последовательно, на одинаковой нагрузке с бюджетом 50000; SCORE_ALPHA=1,
жадная очередь, повторы выключены. По умолчанию конкурсный агент не меняется.
Данные, разметка и эталоны не копируются в образ агента.
