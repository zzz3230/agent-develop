# gaps-v1: случаи, которых нет в других наборах

40 задач, по 10 каждого типа. Набор не заменяет `diverse-v1` и `suite`, а закрывает то, чего в них нет. Он диагностический: задачи маленькие и нацелены на конкретные ошибки, поэтому общий процент решённых здесь не предсказывает результат конкурса.

## Чем отличается от других наборов

| Пробел в других наборах | Что здесь |
| --- | --- |
| Невыполнимых мало (6% в `diverse-v1`) или они однотипны (в генераторе `suite` только «x + y = N» и «факта нет») | 12 невыполнимых, 30%, во всех четырёх типах и девяти разных видов |
| В условиях `suite` есть подсказка «write IMPOSSIBLE instead» | подсказки нет ни в одном условии, как у организаторов |
| Нет задач, которые выглядят невыполнимыми, но решаемы | 7 таких задач: проверяют, не отказывается ли агент зря |
| Формат отличается от официального: нет `workspace/`, `solution.py` вместо `mylib.py`, награды до 10 | точный формат примеров: `workspace/`, `mylib.py` и `test_mylib.py`, официальные хвосты условий, награды 1–5, поле `check` |
| Мало проверок формата ответа | ноль, отрицательное число, число больше 64 бит, строка вместо числа, не-ASCII, точка внутри ответа |
| Скрытые тесты кода не нацелены на узкие исправления | у четырёх задач есть «узкое» исправление, которое проходит видимые тесты и проваливает скрытые |
| Нет кириллицы в коде, BOM и CRLF, очень больших файлов | комментарии и данные на русском, CSV с BOM и CRLF, CSV на 20 000 строк, база из 300 файлов |

## Задачи

| Категория | Задач | Что проверяет |
| --- | ---: | --- |
| `impossible` | 12 | агент не отвечает и не тратит лишнее, когда данных нет или они противоречат друг другу |
| `near_miss` | 7 | агент не отказывается, когда задача только похожа на невыполнимую |
| `answer_format` | 6 | разбор и запись необычных ответов |
| `hidden_tests` | 4 | исправление по смыслу, а не под видимый тест |
| `robustness` | 7 | большие и «грязные» файлы, кириллица, длинные цепочки, правило округления |
| `official_shape` | 4 | обычные задачи в формате примеров, но с новыми вопросами |

Полный список с описанием каждой задачи — в `manifest.json`, поля `category` и `what`. Причина невыполнимости — в поле `reason`.

Невыполнимые:

| Тип | Вид |
| --- | --- |
| math | не указано количество в одном шаге; два противоречащих утверждения; спрашивается то, о чём в условии нет данных |
| data_analysis | нет нужной колонки; вопрос опирается на отсутствующий файл; один заказ записан дважды с разными значениями |
| search | человека нет в базе; два одноимённых человека с разными датами рождения; у компании нет нужного поля; у работодателя нет файла |
| coding | два теста требуют разных результатов одного вызова; тест требует, чтобы int был равен строке |

## Как запустить

Из корня репозитория.

```bash
python benchmarks/gaps-v1/build.py
python benchmarks/gaps-v1/validate.py
```

`build.py` воспроизводимо пересобирает `input/`, `references/` и `manifest.json`; файлы пишутся побайтно, поэтому хеш совпадает на любой ОС. `validate.py` не вызывает модели и проверяет:

- во входах только официальные поля, официальные формулировки и нет слова IMPOSSIBLE;
- исходный `mylib.py` падает на видимых тестах, эталон проходит видимые и скрытые;
- узкое исправление проходит видимые тесты и проваливает скрытые;
- оценщик `evaluation/grade` даёт идеальным ответам максимум, а ответам на все невыполнимые задачи — столько же ложных ответов, сколько невыполнимых задач.

Прогон агента: в контейнер монтируется **только копия `input/`**, в `references/` лежат ответы.

```bash
cp -r benchmarks/gaps-v1/input benchmark-runs/gaps-01
# запустить агента на benchmark-runs/gaps-01, сохранить журнал trajectory.jsonl
python -m evaluation.grade --references benchmarks/gaps-v1 --run benchmark-runs/gaps-01 --trajectory PATH/trajectory.jsonl
```

Оценщик сравнивает числа точно, строки — без учёта регистра и внешних пробелов. Для кода он запускает исходные видимые тесты и `test_private.py`.

## Ограничения

- Задачи составил один человек, и они проверяют наши собственные предположения о финале.
- Невыполнимых 30%: это чуть больше ориентира организаторов 15–25%, потому что цель — покрыть виды, а не повторить состав конкурса. Для проверки выбора задач на конкурсном составе подходит генератор `suite`.
- Модели на этом наборе ещё не запускались, поэтому сложность не измерена.
