# 500 задач для сравнения планировщиков

В репозитории сохранены готовые входы: генерировать их перед запуском не нужно.
В исправленной версии от 12 ноября требование q + offset стоит перед фразой
про answer.txt: раньше у 120 математических экземпляров оно отрезалось
обработчиком условия агента. Старые подготовленные нагрузки нужно создать
заново из обновлённого набора; их хеши изменятся. Прогоны старой версии
не подходят для сравнения правильности на исправленном наборе.
Это 500 экземпляров из 152 исходных семейств четырёх наборов: `diverse-v1`,
`suite-v2`, `gaps-v1`, `tricks-v1`. По 125 задач на математику, таблицы, поиск
и исправление кода. 100 задач не имеют решения по доступным данным.

Награда — случайное целое от 1 до 10, отдельный генератор не использует тип,
сложность или выполнимость. Seed содержимого — 20261112, наград — 20262103.
Случайная награда не означает равного количества задач с каждой наградой.

`train` содержит 300 задач из diverse/suite, `eval` — 200 из gaps/tricks.
Идентификаторы исходных семейств между частями не пересекаются. Однако
родственные алгоритмы могут встречаться в разных источниках: это не 500
независимых алгоритмов и не доказательство переноса на закрытую выборку.
Варианты меняют данные, числовые параметры, пути и окружение; у некоторых
задач кодирования меняется только имя модуля. Семейство записано в manifest,
чтобы варианты одной задачи не попадали в разные фолды при обучении.
Gaps/tricks уже были доступны команде, поэтому eval также не является слепым тестом.

## Подготовить одинаковую нагрузку для всех участников

Из корня репозитория, Python 3.11+, без ключа и дополнительных библиотек:

```powershell
python -m evaluation.prepare_planner_pool --out benchmark-runs/pool-eval-101 --split eval --count 100 --selection-seed 101 --reward-seed 1001
python -m evaluation.prepare_planner_pool --out benchmark-runs/pool-all-101 --split all --count 500 --selection-seed 101 --reward-seed 1001
```

Каталог назначения должен быть новым. Количество кратно 20: сохраняются
равные доли типов и 20% невыполнимых. Максимум для train — 300, eval — 200,
all — 500. `selection-seed` выбирает задачи и порядок, `reward-seed` независимо
назначает награды. Награда одновременно обновляется во входе и эталоне.

Агенту монтировать **только `<out>/input`**. `<out>/references` и manifest
остаются у проверяющего: там есть ответы, признаки выполнимости и скрытые тесты.
Перед каждым запуском нужна свежая копия input, чтобы ответы и изменения
предыдущего агента не попали в следующий запуск.

Пример для уже собранного образа с предикторами (ключ и URL прокси передаются
через окружение, `run_image` сам создаёт свежую копию):

```powershell
python -m evaluation.run_image --image agent-develop:predictor-policies --tasks benchmark-runs/pool-eval-101/input --references benchmark-runs/pool-eval-101 --out benchmark-runs/greedy-101 --hard-budget 6000 --env BUDGET=6000 --env ENFORCE_BUDGET=1 --env PREDICTOR=bge_keywords --env QUEUE_POLICY=greedy --env SCORE_ALPHA=1
python -m evaluation.run_image --image agent-develop:predictor-policies --tasks benchmark-runs/pool-eval-101/input --references benchmark-runs/pool-eval-101 --out benchmark-runs/knapsack-101 --hard-budget 6000 --env BUDGET=6000 --env ENFORCE_BUDGET=1 --env PREDICTOR=bge_keywords --env QUEUE_POLICY=knapsack --env SCORE_ALPHA=1
```

Обученные варианты и сборка описаны в `docs/offline-predictors.md` и
`docs/results/offline-predictors-v2/README.md`. Для исходной очереди используйте
`PREDICTOR=baseline`. Локальное принудительное ограничение выше включается
только для сравнения; конкурсную общую квоту по-прежнему контролирует прокси.

Для честного сравнения фиксируйте одну подготовленную нагрузку, модель,
настройки агента, бюджет и правило остановки. Меняйте только предиктор или
планировщик. Для сравнения жадного алгоритма и рюкзака используйте одинаковые
предикторы и `SCORE_ALPHA=1`. Начните с бюджетов 3000, 6000, 12000;
проверьте, что они действительно заставляют выбирать часть задач.
Не выбирайте лучший seed по результатам. Для следующих повторов заранее
задайте, например, seed наград 1001–1005. Отдельно фиксируйте баллы, расход,
правильные ответы и время. При остановке после запроса возможен перерасход:
также считайте баллы ответов, завершённых до пересечения бюджета.

Обучать предикторы можно по прогонам train с разделением по `family`.
Часть eval оставьте для итогового сравнения; all подходит для нагрузочного
сравнения, но смешивает обучающие и оценочные семейства.
Этот набор не обучает предикторы автоматически и ещё не прогонялся через LLM.

## Проверка и происхождение

```powershell
python -m evaluation.validate_planner_pool benchmarks/planner-500
python -m evaluation.validate_planner_pool benchmarks/planner-500 --coding
```

Вторую команду выполняйте в Linux-окружении агента с numpy, pandas и dateutil.
Она проверяет эталонные исправления всех 100 решаемых задач кодирования
на открытых и скрытых тестах. Первая проверяет состав, хеши входов,
отсутствие скрытых тестов во входах и согласованность наград с эталонами.
Ответы остальных типов получены генераторами исходных наборов; варианты
целочисленной математики дополнительно меняют требуемый ответ на q + offset.
Независимой проверки всех математических эталонов здесь нет.

Генератор: `python -m evaluation.build_planner_pool --out <новый каталог>`.
Все данные занимают около 6 МБ и исключены из Docker-образа агента.
Исходные файлы сохраняются побайтно, включая BOM и CRLF.
