# Инструкции по типам задач

Актуальная конфигурация после AGE-13/23: `age-13-23.md`. Инструкции ниже
сохранены, но лимиты увеличены по типам, схема CSV и контекст поиска
включены по умолчанию. Таблицы исторических запусков ниже относятся к
своим версиям runtime.

`runtime/profiles.py` хранит две измеренные инструкции. Формат финального
ответа одинаковый; меняется только рекомендация о способе работы.

| Тип | Инструкция |
| --- | --- |
| math | baseline |
| data_analysis | baseline |
| coding | economy |
| search | baseline |
| неизвестный тип | baseline |

После более сложной проверки экономная инструкция применяется только к
coding. Для остальных типов сохранена исходная инструкция. Ранее economy существовала только в эксперименте,
поэтому изменение добавляет явный выбор профиля в рабочий запуск.
Формулировки точно совпадают с A/B-тестом в `prompt-economy-ab.md`.
Для математики выигрыш в A/B был всего 0.55%, для CSV 4.13%, для coding
9.64%; это результаты небольшого простого набора, не обещание качества
или экономии на закрытых задачах.

Промежуточная проверка интеграции: реальный run `20261110-012010-686`, рабочий entrypoint,
лимит ответа 600 и 6 шагов. 8/8 исходных примеров, 20/20 локальных баллов;
исходные coding-тесты проходят и не изменены.

В этом прогоне economy ещё использовалась для math и data_analysis.
Затем эти два типа возвращены на baseline после более сложной проверки.
Проверка выбора профиля подтверждает: coding — economy, все остальные —
baseline. Ранее baseline тоже прошёл все шесть не-coding примеров.

Организаторы говорят, что финальные задачи заметно отличаются от примеров,
coding проверяется другими тестами (`rules.md`). Прежние 10 повторов одних
и тех же условий измеряли повторяемость, а не качество на сложных условиях.
Дополнительные синтетические задачи проверяются отдельно; их сложность
не является известной копией финального набора.

## Более сложные условия

16 дополнительных реальных попыток: 8 новых задач × 2 инструкции,
один проход на задачу/инструкцию. Модель qwen3.8-27b-noreason, короткий
bash, 6 шагов, выход до 1200, мягкий предел стоимости 3000.
Эти параметры отличаются от рабочих 600/2500, что ограничивает перенос
результата. В baseline решено 6/8, в economy 5/8. По типам:

| Тип | Baseline | Economy |
| --- | ---: | ---: |
| math | 2/2 | 2/2 |
| data_analysis | 2/2 | 1/2 |
| search | 0/2 | 0/2 |
| coding | 2/2 | 2/2 |

Задачи включают оптимизацию под два ограничения, округление процентов
по дням, ревизии заказов и объединение трёх CSV, восстановление сессий
по событиям, датированные и конфликтующие записи базы знаний, объединение
интервалов и денежные вычисления над CSV с кавычками и переносами строк.
В обеих инструкциях поиск упёрся в 6 шагов; economy также не завершила
расчёт по трём CSV. В этих случаях вместо ответа вернулся служебный текст
Max iterations reached without completion. Такой результат в локальной
оценке считается провалом независимо от слова solved в runtime.

Все 4 coding-попытки прошли дополнительные проверки, не переданные агенту:
150 случайных наборов интервалов, денежный CSV на 200 строк, нечисловые
и бесконечные суммы. Это наши закрытые проверки, а не тесты организаторов.
Исходные тесты не изменены. Приватные тесты лежат на хосте вне входного
маунта и контейнера агента.

Показатель 160/160 на прежних восьми условиях отражал повторяемость
простых задач; более сложный набор выявил реальные ограничения.
Составной CSV в baseline потребовал 2734.6, выше рабочего лимита 2500.
Лимиты 6 шагов/600 выходных/2500 стоимости остаются кандидатами для
отдельной настройки с М1/М3. Этот коммит их не увеличивает.
