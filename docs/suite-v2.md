# Набор задач v2: разработка и отложенная оценка

11 ноября 2026. Воспроизводимый набор из 20 разнообразных задач четырёх типов
с эталонами для независимой проверки. Генератор и эталоны живут только на
хосте: `evaluation/build_suite.py` исключён из Docker-образа, в каталог задачи
агента попадают только `task.json` и `workspace/`.

## Состав

20 шаблонов, по 5 на тип; 4 из 20 (20%) явно невыполнимы. 10 шаблонов —
разработка (dev), 10 — отложенная оценка (holdout). Шаблоны не пересекаются:
holdout проверяет обобщение на другие формулировки, а не на другие числа.

| Тип | Dev | Holdout |
|---|---|---|
| math | `math_loan` — график кредита с округлением HALF_UP; `math_divisible` — включение-исключение на больших числах; `math_underdetermined` — невыполнимо: x + y = N без второго уравнения | `math_grid` — кратчайший путь в лабиринте из файла; `math_business_days` — рабочие дни с праздниками из файла |
| data_analysis | `data_latency` — p95 по nearest-rank с фильтрами и null; `data_transfers` — численность отдела на дату по переводам | `data_dedupe` — уникальные клиенты после нормализации email; `data_growth` — месяц с максимальным приростом, пустые месяцы = 0; `data_missing_rate` — невыполнимо: в rates.csv нет курса нужной валюты |
| search | `search_changelog` — последняя выпущенная версия, где функцию добавили или вернули (отозванные релизы не считаются); `search_actions` — владелец поручения при закрытии по протоколам встреч; `search_not_recorded` — невыполнимо: в базе нет нужного факта | `search_org` — руководитель руководителя на дату по датированным записям; `search_sku` — склад товара на дату с отменёнными перемещениями |
| coding | `coding_semver` — сравнение версий по SemVer 2.0.0; `coding_duration` — разбор строк вида `2d4h30m15s` | `coding_topo` — лексикографически наименьший топологический порядок; `coding_roman` — римские числа в обе стороны; `coding_contradiction` — невыполнимо: тест требует целый корень из 8 |

В каждой части по 2 невыполнимых из 10. Reward берётся из отдельного
генератора случайных чисел в диапазоне 1–10 и не зависит от шаблона и сложности.

## Сборка

```bash
python -m evaluation.build_suite base --output /tmp/suite
# /tmp/suite/dev и /tmp/suite/holdout: input/ (для агента), references/, manifest.json
```

Семя по умолчанию 20261111. Повторная сборка даёт те же файлы: хэш входов dev
`07c29322f1fd792f…`, holdout `69fde8f413f16c94…` (полные значения в manifest.json).

Для каждой задачи coding генератор при сборке проверяет, что эталонное решение
проходит видимый и скрытый тесты, а исходный код с ошибкой проваливает видимый.

## Нагрузка до 100 задач

```bash
python -m evaluation.build_suite load --output /tmp/load --count 100 --seed 7
```

Быстрый генератор создаёт новые экземпляры только dev-шаблонов (случайные
числа, имена, файлы). 100 задач: по 20 выполнимых каждого типа, 20
невыполнимых. Holdout-шаблоны для нагрузки требуют явного `--allow-holdout`.

## Проверка

```bash
cp -r /tmp/suite/dev/input /tmp/run && TASKS=/tmp/run python run_agent.py
python -m evaluation.grade_suite --suite /tmp/suite/dev --run /tmp/run --trajectory /tmp/harness/trajectory.jsonl
```

`grade_suite` сравнивает `answer.txt` с эталоном (целое число или точная
строка). Для coding принимается только `DONE`, если в копии рабочего каталога
с восстановленным видимым тестом проходят видимый и скрытый тесты. Для
невыполнимых баллов нет; любой ответ, кроме отсутствия файла или IMPOSSIBLE,
считается ложным. Отчёт: баллы, решено, ложные ответы, расход по журналу,
время, разбивка по типам.

Проверка самого проверяющего: эталонные ответы и решения дают 8/8 выполнимых
и 0 ложных в каждой части (32/32 и 45/45 баллов); неправильные ответы и
подмена видимого теста дают 0 баллов и 2 ложных ответа. Сквозной прогон
`run_agent.py` с имитацией модели проходит без ошибок.

## Правило использования

Настраивать инструкции, лимиты, очередь и повторы только на dev и на
нагрузочных экземплярах dev-шаблонов. Holdout запускать один раз для
окончательной оценки выбранной конфигурации, не меняя её по результату.
