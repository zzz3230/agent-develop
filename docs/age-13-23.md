# AGE-13 и AGE-23: лимиты, остановки и качество

Обновление 11 ноября: общий бюджет теперь авторитетно контролирует прокси,
локальные пределы попытки продлеваются по прогрессу. Актуальные значения,
число тестов и результаты новой проверки — в `adaptive-limits.md`.
Этот документ сохраняет историю предыдущего фиксированного профиля.

10 ноября 2026. База origin/main `9feaf76`. Используем готовый ReActAgent,
штатный bash, max_iterations, timeout команды и lifecycle rails OJ 0.1.19.
Нового агентного цикла и новых моделей нет. Модель одна на задачу:
qwen3.8-27b-noreason.

## Что изменено

- Лимиты попытки вынесены в `runtime/attempt_policy.py`; М3 может передать
  свой `AttemptLimits` в `attempt`, не переписывая агента.
- `AttemptRail` ограничивает штатный timeout команды и останавливает три
  одинаковые ошибки инструмента, если исходники не изменились. После
  правки исходников счётчик сбрасывается. Учитываются команда и текст
  ошибки, косметическое описание вызова не мешает распознаванию повтора.
- Аргументы вызова сохраняют исходный JSON-формат, чтобы hook не менял
  формат истории для OpenAI-compatible API.
- Стоимостный лимит или таймаут одной задачи не считаются ошибкой API и
  не запускают остановку всего прогона после четырёх таких случаев.
- Тесты coding восстанавливаются и при исключениях. Если код уже проходит
  неизменённые тесты, DONE сохраняется даже при сбое модели после правки.
- Служебное сообщение Max iterations reached without completion не
  принимается за ответ. `check=exact_int` используется для проверки
  формата; `expected` runtime не загружает.
- CSV_SCHEMA включён по умолчанию: агент получает ограниченную схему,
  примеры строк и короткие множества значений, а вычисляет через Python
  в штатном bash. Ошибка подготовки или схема >12000 символов возвращает
  обычный путь. CSV_SQL остаётся отдельным выключенным экспериментом.
- Поиск получает ограниченные выдержки с именами файлов. Маленькая KB
  передаётся целиком, большая — с простым лексическим ранжированием.
  Эталоны/task.json/answer.txt не читаются. Модель сохраняет доступ к
  обычному bash для проверки источников и дальнейшего поиска. Экономная
  инструкция в search не включена.

## Настройки попыток

| Тип | Шаги OJ | Выход на запрос | Мягкий лимит стоимости | Время попытки |
| --- | ---: | ---: | ---: | ---: |
| math | 6 | 1200 | 2500 | 120 с |
| data_analysis | 8 | 1200 | 4000 | 180 с |
| search | 10 | 900 | 3500 | 150 с |
| coding | 10 | 1600 | 5000 | 240 с |

Штатный timeout каждой bash-команды ограничен 30 секундами; фоновые
вызовы отключены. Время попытки также ограничено остатком общего времени.
Лимит стоимости мягкий: проверяется перед следующим запросом, завершившийся
запрос может его превысить. Это верхние ограничения, а не обещанный расход.
Глобальная политика бюджета М1 и очередь М3 этим изменением не заменяются.
В журнале `attempt_start` сохраняет выбранные лимиты, а `outcome` — причину
завершения. Короткий правильный ответ не трактуется как отсутствие прогресса.

## Проверка

Корпус: 8 исходных примеров, 8 разработческих сложных задач, 8 новых
контрольных условий, 2 случая с отсутствующими данными. Все исходные
эталоны находятся в `evaluation/fixtures`, который исключён из Docker.
Во входных копиях удалён `expected`, сохранён `check`. Отдельные coding
проверки скрыты от агента: случайные интервалы, денежный CSV, нормализация
путей и суммы скользящих окон. Это наши синтетические тесты, не тесты жюри.

| Набор | Старый образ | Новый образ |
| --- | ---: | ---: |
| Исходные примеры | 8/8 | 8/8 |
| Сложные разработческие | 7/8 | 8/8 |
| Новые контрольные | 6/8 | 8/8 |
| Выполнимые всего | 21/24 | 24/24 |
| Баллы по этому корпусу | 33/36 | 36/36 |
| Отсутствующие данные: нет выдуманного ответа | 2/2 | 2/2 |
| Расход с инфраструктурными повторами | 15622.1 | 12221.3 |

В таблице учтены только повторы после подтверждённых 503, а не повторные
попытки улучшить неверное решение. Первые полные прогоны дали 20/24 у
старого (три провала поиска и один 503) и 21/24 у нового (три 503).
После освобождения прокси повторены соответствующие задачи. Расход
неуспешных API-попыток, если записан usage, включён. За ошибки без usage
возможен неизвестный расход на стороне прокси; журнал не является
независимым биллингом.

Финальный образ после исправления JSON-аргументов и сохранения проверенного
coding-результата отдельно прошёл 9/9 ключевых условий, включая три случая
503 и ещё шесть регрессий. Шесть дополнительных успешных регрессий не
подменяют результаты первых полных прогонов и не включены повторно в
сравнение стоимости таблицы. Полный набор не запускался заново на финальном
байт-в-байт образе: изменение сериализации проверено unit/native тестами
и указанными 9 реальными случаями. Различия ограничений, контекста и
промптов оценены совместно; это не изоляция вклада каждого изменения.

13 автоматических проверок прошли в read-only контейнере без внешней сети.
Локальный mock API проверяет настоящий ReActAgent: остановка после 3
одинаковых ошибок, TaskLimitExceeded и BudgetExhausted с сохранением типов
исключений. Тесты также проверяют DONE, короткий ответ, восстановление
тестов при таймауте и продолжение общего прогона после 4 лимитов задач.

```sh
docker build -t agent-develop:m2-limits-final .
docker run --rm --read-only --tmpfs /tmp:rw,size=256m --network none -e PYTHONPATH=/app --workdir /tmp --entrypoint python agent-develop:m2-limits-final -m unittest evaluation.test_attempts evaluation.test_sql_tables evaluation.test_sql_profile
docker run --rm --read-only --tmpfs /tmp:rw,size=256m --network none -e PYTHONPATH=/app --workdir /tmp --entrypoint python agent-develop:m2-limits-final -m evaluation.check_attempt_stop
python -m evaluation.validate_run --run PATH_TO_RUN
```

Небольшой корпус и один основной проход не гарантируют качество на
финальных задачах. Новые контрольные условия не использовались для
подстановки ответов или специальных обработчиков. Для окончательного
выбора остаётся независимый набор М3 и репетиция общего бюджета.
