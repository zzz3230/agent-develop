# Проверка примеров: AGE-8 и AGE-9

Проверяем готовую конфигурацию ReActAgent на настоящем конкурсном прокси.
Восемь исходных задач храним отдельно от репозитория. В копиях для агента
удаляем только `expected`, сохраняя `check`, как в закрытой выборке.
В исторических прогонах AGE-8/AGE-9 удалялись оба поля; скрипт подготовки
исправлен перед сравнением моделей. Оригиналы нужны независимому проверяющему.

## Независимая проверка сохранённого прогона

```powershell
python evaluation/check_examples.py --source "C:\Users\hilis\hackathon-task\task-dir\task-dir" --run "C:\Users\hilis\hackathon-task\proxy-runs\RUN_DIRECTORY" --output "C:\Users\hilis\hackathon-task\proxy-runs\RUN_DIRECTORY\checked.json"
```

`--run` содержит папки `tasks/` и `logs/`. По умолчанию для проверки кода
используется локальный образ `agent-develop:c789e74`; другой задаётся через `--image`.

Проверяющий не обращается к модели и не расходует прокси-бюджет:

- числа сравниваются как целые, без извлечения числа из пояснений;
- строки сравниваются с сохранением регистра, после удаления внешних пробелов;
- coding требует `DONE`, неизменных исходных тестов и их успешного запуска;
- исходные тесты запускаются против копии полученного кода в отдельном Docker
  без сети, с read-only файлами и ограничениями ресурсов;
- расход и число вызовов берутся из журнала, а правильность — из проверки ответа.

Это локальная строгая проверка примеров, а не воспроизведение скрытого
проверяющего конкурса. По новым ответам организаторов строки нормализуются,
но точный алгоритм ещё неизвестен; здесь сохраняем регистр, чтобы не скрывать
расхождения. Coding в финале проверяется другими тестами, поэтому прохождение
видимых тестов не гарантирует финальных баллов. Стоимость берётся из нашего журнала и не является
независимой сверкой биллинга прокси. Совпадение файлов тестов после запуска
не доказывает отсутствие временных изменений внутри попытки; отказ runtime
из-за изменения тестов также виден в поле `outcome` отчёта.

JSON содержит результаты по каждой задаче, фактический ответ, эталон,
расход, число вызовов, баллы и исходный `outcome`. Не запущенные задачи
помечаются `not_run`. Код возврата 0 означает прохождение всех восьми примеров,
1 — неполный или неуспешный набор.

## Прогон всех примеров и причина сбоя

10 ноября (Новосибирск), базовый образ `agent-develop:c789e74`, прогон
`20261110-001428-369`: 7/8, 18/20 баллов на видимых примерах, 3563.6 единицы
по журналу, 72.2 секунды. Все шесть задач AGE-8 прошли. `coding_0003`
прошла 6 исходных тестов, `coding_0007` не исправлена и не имеет ответа.
В обеих папках файлы тестов совпали с оригиналами.

Повтор `coding_0007` в `20261110-001605-882` подтвердил проблему штатных tools:
после чтения через `cat` инструмент `edit_file` требует чтение через
`read_file`; тот возвращает `Cannot release a lock ... that is not held by
this task through this wrapper`. Результат: снова провал, стоимость 1074.9.
Это наблюдаемая ошибка в текущем окружении, а не утверждение о причине
внутри библиотеки или всех версиях OJ.

Кандидат исправления после обновления базы до `4fd6042`: использовать только
штатный `bash` для всех coding-задач. Python через bash может читать и
редактировать файлы и запускать тесты. Собственный инструмент или цикл агента
не добавляем; промпт, модель, число шагов и лимит ответа сохраняем.
Настройка не содержит имён примеров, эталонов и конкретных исправлений кода.
Временные исправленные копии, которыми проверялся оценщик, не используются
в прогонах агента и не входят в конкурсный образ.

Промежуточный прогон `20261110-002241-544`, только замена coding-tools на
`bash`: обе coding-задачи прошли исходные тесты, файлы тестов не изменены.
Однако `math_0000` вернула пояснение с Markdown вместо чистого числа;
строгий локальный результат — 7/8 и 15/20. Промежуточную версию поэтому
не считаем улучшением общего качества. Для следующего прогона в общий
SYSTEM добавлено требование одной строки без пояснений и Markdown, а для
числового ответа — только число. Конкретные значения не извлекаем из текста
эвристикой и не подставляем из примеров.
