## Выводы

- Разброс между одинаковыми прогонами — до ±5 баллов из 32: одна задача-ловушка (search_0000) стоит 3000–4000 и почти всегда не решается. Один прогон на 10 задачах не различает изменения по ±3 балла; для решения 12 ноября нужен отложенный набор на 24 задачи (`docs/release-runbook.md`).
- Очередь сама по себе выбирает поиск первым (дешёвая оценка, высокий reward) и поэтому раньше натыкается на ловушку; вместе с адаптивными лимитами (короткий старт) — лучший результат прогона 2. Отдельно `QUEUE=1` без адаптивных лимитов хуже базы в прогоне 2.
- Во всех прогонах решённые search стоили не больше 1739, неудачные — от 2872. Потолок search 3500 можно понизить до ~1800, но это вывод по одной задаче dev-набора; проверять на отложенном наборе, а не подгонять по dev.
- Набор v2: эталоны совпали со всеми верными ответами модели; ложных ответов на невыполнимые 0 во всех прогонах.
