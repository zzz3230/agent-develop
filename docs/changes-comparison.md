задачах и бюджете, по одному изменению за раз; полный перебор комбинаций не
делался. Незавершённая на тот момент AGE-12 не ожидалась, очередь добавлена
отдельной строкой по её замеру (`docs/task-queue.md`).

## Как читать

- Полезны: экономная инструкция только для coding, схема CSV и контекст
  поиска, остановка повторяющихся ошибок, очередь.
- Выключить или не включать: экономную инструкцию для search; повторы.
- Под вопросом: адаптивные лимиты. Прямое сравнение с фиксированным
  профилем дало 35/36 против 36/36 и почти одинаковый расход; это по одному
  прогону, разница в одну задачу (промах по смыслу, а не из-за лимита).

## Ограничения

Строки получены в разных сериях, а не одним прогоном на общем бюджете:
живого ключа прокси в этой среде не было. В каждой строке задачи и модель
внутри сравнения одинаковые. Строка очереди — воспроизведение записанных
реальных попыток.

## Живой повтор одной командой

```bash
python -m evaluation.build_suite base --output /tmp/suite
LLM_BASE_URL=... LLM_API_KEY=... \
python -m evaluation.compare_changes --suite /tmp/suite/dev --budget 30000 --out /tmp/cmp
```

Варианты: `base` (всё выключено), `+instructions`, `+adaptive_stops`,
`+csv_search_prep`, `+queue`, `all_on` — 6 прогонов вместо 32 комбинаций.
Каждый вариант получает свежую копию задач, отдельный журнал и независимую
проверку `grade_suite`. Скрипт печатает таблицу: баллы, решено, ложные
ответы на невыполнимые, расход, время, разница с базой. Выключатели:
`PROMPT_ECONOMY`, `ADAPTIVE_LIMITS`, `CSV_SCHEMA`, `SEARCH_CONTEXT`, `QUEUE`, `RETRY`.
Бюджет 30000 на 10 задачах выбран так, чтобы порядок и расход имели значение.
Holdout-часть использовать только для окончательного замера.
