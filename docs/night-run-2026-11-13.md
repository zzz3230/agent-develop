## Выводы
1. **MiniLM-предиктор: +68 очков (+19%) при режущем бюджете** — стабильно во всех 3 повторах.
   Baseline на pool200 не решил ни одной data_analysis (очередь ставит их в конец и бюджет кончается).
   Когда бюджета хватает на всё (c100@100k), предиктор не важен (разница 7 очков ≈ шум).
2. **Guards: −10…−30% трат на невыполнимые** (c100: −7.2k, gaps: −6.2k). При режущем бюджете это
   конвертируется в очки (+16 к MiniLM, +70 к baseline — у baseline много места для экономии).
   При нережущем бюджете — около −3 очков (−1.5 верных); систематически потерянных задач нет
   (ни одной задачи, решённой в обоих прогонах без guards и проваленной в обоих с guards).
3. **Повтор при 429 обязателен**: без него 4 ответа 429 подряд завершали весь прогон.
4. Невыполнимые всё ещё ~30–40% трат; ложных «IMPOSSIBLE»/ответов 8–10 на 100 задач — следующая цель.

## Решение для сдачи
Организаторы прогнозируют, что бюджета на финале хватит примерно на 30% задач. Наш режим pool200@50k
(решено ~31% задач) — именно такой, поэтому решающая строка — pool200: **MiniLM + guards, 444 очка
против 361 у baseline (+23%)**. Это конфиг по умолчанию в образе (`ENV` в Dockerfile):
`QUEUE=1 QUEUE_POLICY=greedy PREDICTOR=embedding TIGHT_CAPS=1 SEARCH_PROGRESS=entity STAY_INSIDE=1`,
плюс повтор запросов при 429. Любой параметр можно переопределить через `-e`.
