# Сравнение моделей и инструментов

Эксперимент 10 ноября 2026. Цель — выбрать модель и набор штатных инструментов
по правильности, затем по стоимости. Это небольшой разведочный эксперимент,
а не доказательство качества на закрытой выборке.

## Метод

Четыре разрешённые модели, один системный промпт ReActAgent, температура 0,
до 6 шагов, до 1200 выходных токенов на запрос, таймаут 150 секунд и мягкий
предел стоимости попытки 3000. Последовательный запуск под конкурсными
ограничениями Docker. Эти лимиты относятся к эксперименту; рабочий runtime
не переключается автоматически на результаты сравнения.

Первый этап: 8 задач × 4 модели × один коротко описанный штатный bash =
32 попытки. На каждый тип одна открытая задача и одна новая: арифметика
с округлением, фильтрация CSV с вычислением выручки, связь сущностей в
локальной базе знаний, исправление общих функций Python. Во все модели
передаются одинаковые файлы и условия, рабочая папка копируется заново.

Второй этап: для самого экономного успешного кандидата каждого типа
сравниваем исходный bash с полным описанием и расширенный набор tools
с короткими описаниями. База для сравнения — короткий bash первого этапа.
Полезность набора и полезность сокращения описания оцениваем отдельно.

Эталоны находятся снаружи контейнера агента. Из входа удалён только
`expected`; поле `check` сохранено. Проверка выполняется на хосте после
запуска. Для coding запускаются оригинальные видимые тесты в отдельном
контейнере без сети и проверяется, что тесты не изменены.

Для стоимости берём `usage.input_tokens / 10 + usage.output_tokens`.
Прокси включает reasoning в completion, поэтому не прибавляем его второй
раз. Отдельная настройка счётчика существует только в benchmark: при
полном usage не берём максимум с оценкой по символам, как делает текущий
production MeteredModel. При отсутствии usage используется его fallback,
а результат помечается оценочным. Учитываются все запросы попытки, включая
неуспешное решение. Отказы до получения usage могут иметь неизвестную
стоимость. Токены кеша считаем без скидок.

Одно прохождение каждой пары; нет статистики по случайным повторениям.
Новые задачи используются для сравнения конфигураций и после этого не
считаются отложенными. Для окончательного выбора нужен отдельный набор М3.
Результат относится к текущему OJ и лимиту ответа 1200, а не ко всем
возможным конфигурациям модели.

## Модели: результат первого этапа

Все модели решили 8/8 (по 2/2 каждого типа). Ниже средняя стоимость
одной попытки, включая все запросы; инструменты — только короткий bash.

| Тип | 3.8-27b-noreason | 3.6-35b-a3b-noreason | 3.8-27b | 3.6-35b-a3b |
| --- | ---: | ---: | ---: | ---: |
| math | 198.8 | 324.0 | 470.1 | 765.2 |
| data_analysis | 274.8 | 628.1 | 691.6 | 554.0 |
| search | 421.2 | 372.8 | 406.5 | 575.5 |
| coding | 661.1 | 928.5 | 681.9 | 946.2 |

На этих задачах `qwen3.8-27b-noreason` — экономная исходная модель для
math, data_analysis и coding; `qwen3.6-35b-a3b-noreason` — кандидат для
search. Разница search с текущей исходной моделью около 11.5%, но это
всего две задачи. `qwen3.8-27b` в coding стоит почти столько же (+3.1%)
и в этом прогоне быстрее; его имеет смысл проверить на трудном коде
отдельно. На лёгких задачах преимуществ reasoning по правильности нет,
поскольку все кандидаты справились.

Reasoning-модели в этом запуске работают через OJ с лимитом ответа 1200.
Предыдущий единичный пустой ответ с лимитом 600 не доказывает общую
несовместимость. Причину прежнего пустого ответа этим экспериментом
не устанавливаем: одновременно отличаются задачи и промпт.

Первый этап: 109 запросов, 17800.4 единицы стоимости, ни одного
оценочного usage. Артефакты: `C:\Users\hilis\hackathon-task\model-comparison\stage1`
(`results.jsonl`, `usage.jsonl`, `graded.json`, копии рабочих файлов).

## Инструменты: результат второго этапа

Для каждого типа используется выбранная на первом этапе модель. Каждая
ячейка — средняя стоимость двух задач; стоимость неуспешной попытки тоже
включена. Перечислены доступные агенту инструменты, а не обещание, что он
вызовет каждый из них.

| Тип | Короткий bash (база) | Полное описание bash | Больше tools, короткие описания |
| --- | ---: | ---: | ---: |
| math | 198.8, 2/2 | 515.6, 2/2 | bash + read: 225.6, 2/2 |
| data_analysis | 274.8, 2/2 | 829.6, 2/2 | bash + read: 580.0, 2/2 |

Короткое описание bash на этом наборе связано с сокращением средней
стоимости примерно на 50–67% относительно полного штатного описания.
Это сравнение полных попыток, включая изменение поведения модели, а не
изолированная цена одной схемы. Дополнительные tools здесь не улучшили
правильность и увеличили расход. На новой coding-задаче расширенный набор
исчерпал 6 шагов, оставив исходный код неисправленным. Результат согласуется
с ранее обнаруженной проблемой read/edit, но не доказывает, что всякое
использование этих tools завершится ошибкой.

## Практический выбор

Для следующей отложенной проверки предлагается короткий штатный bash
на всех типах. Модель по умолчанию — qwen3.8-27b-noreason; для search
кандидат — qwen3.6-35b-a3b-noreason. Разницу моделей на двух задачах
не следует считать устойчивым рейтингом. Для сложного coding отдельно
сравнить qwen3.8-27b: на этом наборе он близок по расходу к noreason.

Production-профили автоматически не изменены. В частности, работающий
runtime всё ещё использует 600 выходных токенов, а тестирование проведено
при 1200. Повышать лимит и включать маршрутизацию следует после отложенной
проверки вместе с М1/М3, сохраняя одну модель внутри каждой задачи.

## Уточнение после 160 повторных попыток

Проведено ещё по 10 запусков каждой задачи на двух noreason-моделях.
Обе дали 80/80, каждая задача — 10/10. Но прежнее предположение о выгоде
3.6 для search не подтвердилось: средний расход 3.8 составил 341.1 против
372.8 у 3.6. На всех четырёх типах средний расход ниже у 3.8-noreason.
Обновлённая рекомендация — один короткий bash и qwen3.8-27b-noreason
как базовый кандидат для всех типов. Это вывод по данной небольшой
выборке, а не гарантия решения финальных задач. Детальные результаты,
разброс и счёт по каждой задаче — в `model-stability.md`.
