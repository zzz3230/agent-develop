# Предварительно обученные оценки успеха и расхода

Эксперимент сравнивает текущую очередь из main (945ecb7), очередь с обычными признаками и очередь с обычными признаками плюс эмбеддинги. Решатель, модель qwen3.8-27b-noreason, промпты, инструменты и лимиты попыток одинаковые. По умолчанию остаётся исходная очередь; варианты включаются `PREDICTOR=numeric` и `PREDICTOR=embedding`.

## Что обучается

Логистическая регрессия предсказывает вероятность правильного решения. Ridge-регрессия предсказывает ожидаемый расход непосредственно в токенах. Расход включает вход/10+выход, в том числе неудачные попытки. Разметка успеха берётся из независимой проверки ответов и дополнительных тестов кода. Статус `solved` не используется как правильность. Начальный вариант с log-расходом и слабой регуляризацией плохо прошёл групповую проверку и был заменён до первого контрольного прогона.

Регуляризация выбирается только по пяти обучающим группам: C из [0.0001, 0.001, 0.01, 0.1, 1] по Brier score, alpha из [10, 100, 1000, 10000] по средней квадратичной ошибке расхода. Выбраны C=0.0001 и alpha=1000 для обычных признаков, C=0.001 и alpha=100 для эмбеддингов. Поэтому опубликованные групповые метрики являются метриками подбора и могут быть оптимистичны; независимая оценка — последующие контрольные прогоны. Все параметры и файлы моделей зафиксированы до них, после просмотра контрольных результатов они не меняются.

Обычные признаки: тип, длина и слова требований в условии, число и размеры файлов, форматы, число строк в ограниченной выборке содержимого, ширина таблицы, объём кода и публичных проверок. Считывается не более 256 КиБ содержимого, не более 16 КиБ из одного файла, учитываются не более 512 файлов. Это приближённые признаки, а не полное чтение таблиц. ID, reward, имена каталогов, готовые ответы и скрытые проверки в признаки не входят. Reward применяется только при ранжировании: reward*p/cost.

Во втором варианте добавляются 384 числа от `all-MiniLM-L6-v2`, INT8 ONNX, revision 1110a243fdf4706b3f48f1d95db1a4f5529b4d41. Кодируется только условие, не содержимое всех файлов. Длинное условие разбивается на перекрывающиеся фрагменты, максимум 8; каждый ограничен 256 токенами энкодера. Нормализованные векторы усредняются. Сам энкодер не дообучается. Его веса и токенизатор занимают 23 513 349 байт; загрузка происходит при сборке, во время конкурса доступа к Hugging Face нет.

В очередь попадают фиксированные прогнозы на каждую задачу. Неудачные попытки во время соревнования не переобучают эти два предиктора. Текущая очередь baseline сохраняет исходное обновление статистики по типам. Включение `QUEUE=0` отключает и обученное ранжирование. Остаток глобального бюджета остаётся оценкой; ноль не прекращает конкурсный запуск.

## Данные и честность сравнения

Обучение: 100 задач исправленного benchmark100 и 40 задач разработки diverse-v1. Для них сняты новые прогоны текущего решателя без очереди. Старые журналы иных версий и сломанного filelock в обучение не включены. Сбор должен закончиться полностью; попытки без списанных токенов исключаются из обучения стоимости. Повторы одного шаблона объединены в группы; GroupKFold на пяти частях проверяет перенос между группами. Нормализация учится внутри каждой обучающей части. Гиперпараметры фиксированы до контрольного сравнения. Получено 140 строк, 98 правильных ответов, 60 групп. Обучающие прогоны потребовали 150145.2 взвешенного токена.

Контроль: 24 задачи diverse-v1 holdout и 10 задач suite-v2 holdout. Эти входы не используются при обучении моделей и подборе коэффициентов. Разные наборы могут иметь связанные алгоритмические идеи, поэтому разбиение по ID семейств не доказывает полной семантической независимости. Прежний полный прогон diverse-v1 уже был показан команде: это отложенная выборка для обучения данного предиктора, а не никогда не виденная командой выборка.

Три повтора, seeds порядка 101/102/103. Порядок выполнения вариантов вращается, чтобы уменьшить зависимость от времени работы прокси. Бюджет эксперимента 12000 взвешенных токенов выбран заранее, поскольку на лёгком наборе все варианты могут уложиться в 100000 и влияние очереди исчезнет. Это диагностическая проверка планирования, а не прогноз баллов на конкурсных 100000. Остановка задаётся только явно для эксперимента (`ENFORCE_BUDGET=1`); расход может превысить границу одним ответом. В отчёте указывается фактическое превышение. Причина остановки, все списанные вызовы и незавершённые задачи сохраняются.

## Ограничения ресурсов

Каждый запуск получает read-only root, tmpfs /tmp 2 ГБ, не более 8 CPU, memory 16g, pids 512, deadline 3600 секунд; сам агент завершает работу через 3300. API-ключ передаётся только через окружение и удаляется перед выполнением инструментов. Во время итогового сравнения варианты запускаются последовательно, не более одной агентной сессии одновременно. Обучающие измерения могут собираться двумя сессиями (меньше разрешённых пяти).

Общий для всех вариантов образ использует filelock 3.25.0: в main requirements.lock снова 4.2.9, с которым ранее подтверждена несовместимость файловых инструментов OJ. Это зафиксированное отличие общего окружения эксперимента, а не преимущество только одного варианта. При подготовке конкурсного образа совместимость и закрепление зависимости нужно проверить отдельно.

Предварительный замер в контейнере без сети: загрузка энкодера 0.634 с, кодирование 100 одинаковых коротких условий 7.667 с, peak RSS процесса 113244 КиБ. Образ с зависимостями и энкодером до добавления обученных JSON-моделей — 352940368 байт. Это не полный замер агента на реальных задачах. При итоговых прогонах Docker stats снимается примерно раз в 10 секунд: выборочный максимум памяти может пропустить кратковременный пик, но жёсткий memory limit действует постоянно. В локальном Docker VM фактически доступно меньше заявленных 16 ГБ.

## Повторение

1. Установить зависимости обучения из evaluation/predictor-training-requirements.txt в отдельное окружение. Не менять библиотеки конкурсного агента для обучения.
2. Выполнить `python -m evaluation.download_encoder` при сборке; revision закреплён, SHA256 сохранены в predictors/encoder/provenance.json. Веса исключены из Git, но должны быть в Docker build context. Модель: https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2, лицензия Apache-2.0.
3. Указать `PREDICTOR_TRAIN_SUITE` на исправленный benchmark100 с input, references и manifest.json. Подготовить базовый образ командой `docker build -t agent-develop:predictor-base .`; он использует совместимый filelock из requirements.lock. Передать ключ и URL прокси через окружение. Предикторы относятся к текущей конфигурации qwen3.8-27b-noreason с адаптивными лимитами, схемой CSV, контекстом поиска и экономной инструкцией для coding; для другой модели или политики попытки нужны отдельные измерения и обучение.
4. `python -m evaluation.predictor_experiment collect`, затем `python -m evaluation.train_predictors`. Генератор старого набора — evaluation/generate_suite.py. Его условия содержат инструкции по инструментам и отличаются от diverse-v1; перенос проверяется отдельно, это ограничение данных обучения.
5. `docker build -f evaluation/Dockerfile.predictors -t agent-develop:predictors .` Образ не содержит обучающие входы и эталоны, только коэффициенты и encoder. sklearn для применения моделей не нужен; линейные прогнозы вычисляются обычным Python.
6. `python -m evaluation.predictor_experiment compare`, затем `python -m evaluation.predictor_experiment regrade`. После пересчёта команда сама печатает сводку; `python -m evaluation.report_predictors` сохраняет компактный отчёт и аудит ресурсов в docs/results/offline-predictors-v1.

Все сырые результаты остаются в benchmark-runs/predictors-v1 (исключён из Git). Выводы делаются по всем трём повторам, не по лучшему. Для включения нового предиктора по умолчанию нужен выигрыш в баллах при учёте стоимости и ресурсов; меньшая ошибка регрессии сама по себе этого не доказывает.
